# Гостевые QR-пропуска: анализ и дизайн

Статус: черновик, первичный анализ.
Ветка: `arena/0facc7e7-change-pin-basipaero`

## 1. Что даёт библиотека Домиленд (`public-api.domyland.ru/smart-home/buildings/pass/`)

Документация описывает **облачный** API управления пропусками по помещению (`placeId`):

| Метод | Эндпоинт | Назначение |
|---|---|---|
| POST | `~/pass/` | Создать пропуск (человек или авто) |
| POST | `~/pass/` | Отменить пропуск (`passId`, `placeId`) |
| GET  | `~/pass/share` | Получить QR-код для пропуска (`placeId`, `passId`) |

Ключевые поля создания:
- `placeId` — помещение или парковочное место;
- `isPermanent` — постоянный/временный;
- `fullName` — ФИО гостя;
- `accessLevelId` — `1` Гость, `2` Строитель, `3` Курьер;
- `activeFrom` / `activeTo` — окно действия (unix timestamp);
- `vehicle` — для авто (`regNumber`, `regNumberRus`, `carModel`), `parkingId`;
- `comment`.

Авторизация: параметр `token` в query-строке.

**Вывод:** Домиленд умеет создавать временный пропуск и отдавать QR. Но документация не говорит, **кто и как проверяет этот QR на панели** (облако или локальная панель). Это главный вопрос интеграции.

## 2. Что умеет домофон BAS-IP AA-14FB

По данным производителя и дистрибьюторов:
- открытие замка по **QR-коду**, **гостевой ссылке**, PIN-коду, карте, лицу, из приложений BAS-IP Intercom/UKEY/Link;
- **открытый API** (JSON REST), дублирующий веб-интерфейс; в новых прошивках — также **MQTT(S)**;
- identifier-ы (QR, PIN, карта) создаются в памяти панели с **временным профилем** (`time profile`) и **лимитом количества проходов** (passes);
- панель сама проверяет QR локально, без облака.

Эндпоинты API (из публичного описания BAS-IP для мультиабонентских панелей, API 1.8.0):
- `POST /access/identifiers/item` — создать идентификатор (возвращает `uid`);
- `PATCH /access/identifiers/item/{uid}` и `DELETE /access/identifiers/item/{uid}` — изменить/удалить;
- `POST /access/identifiers/item/{uid}/timeProfile/{tpUid}` — привязать временной профиль;
- `POST /access/timeprofile/item` — создать временной профиль;
- `POST /apartment/item/{apartmentUid}/identifier/{identifierUid}` — привязать к квартире;
- `GET /access/identifiers/items/list` — список;
- `POST /access/identifiers/link/update`, `POST /access/identifiers/link/delete` — пакетная работа по `link_id`.

Важные ограничения:
- Wiegand-выход не передаёт QR/PIN/лицо на сторонние контроллеры (только через модуль SH-12).
- Полная документация API доступна только после регистрации на developers.bas-ip.com.
- Заводской пароль веб-интерфейса `admin / 123456` — его обязательно менять на каждой из 38 панелей (см. репозиторий-предок `Change-pin-BasIpAERO`).

## 3. Предлагаемая архитектура (выбрана локальная)

```
[Мобильное приложение Домиленд]
          │ HTTPS (через облако Домиленд или напрямую, см. п. 5)
          ▼
[Guest service на mini PC, объект]
   ├── создаёт временный QR-идентификатор в панели BAS-IP (POST /access/identifiers/item)
   ├── привязывает time profile (окно активности) и лимит проходов
   ├── отдаёт приложению QR-содержимое / изображение
   ├── отзывает пропуск (DELETE identifier) при отмене или истечении
   └── ведёт журнал выдачи (кто, кому, когда, для какой панели)
          │ LAN
          ▼
[Панели BAS-IP AA-14FB × 38] — проверяют QR локально, работают без интернета
```

Почему локально:
- панель открывает дверь без облака (нет зависимости от интернета);
- срок действия истекает на самой панели;
- не нужно менять облако Домиленд, если его API не умеет публиковать QR на панели.

Компоненты для реализации (после получения данных):
1. **Клиент BAS-IP** — обёртка над REST API панели (аутентификация, создание/отзыв identifier, time profile).
2. **Guest service** — HTTP API для приложения: `POST /guest-passes`, `GET /guest-passes`, `DELETE /guest-passes/{id}`, `GET /guest-passes/{id}/qr`.
3. **Планировщик** — очистка истёкших пропусков на панелях.
4. **Журнал** — БД SQLite на mini PC.
5. **Мобильный экран** в приложении Домиленд: форма гостя (имя, даты, квартира/панели), список активных пропусков, показ QR.
6. **Тесты** с мок-панелью.

## 4. Что нужно уточнить

1. **Версия прошивки** и **IP-адреса** 38 панелей (пришлёт пользователь). Нужно, чтобы понять, есть ли REST API 1.7/1.8 и MQTT, и поддерживается ли QR-идентификатор для данной модели.
2. **Доступ к полной документации API** (регистрация на developers.bas-ip.com или документ от поставщика). Нужны: способ аутентификации в API, формат QR-содержимого, возвращает ли панель QR-строку при создании идентификатора.
3. **Стек мобильного приложения** (React Native, Flutter, нативный). Репозиторий приложения пока не передан.
4. **Работает ли Домиленд с облачным API `pass/`** для этих же объектов. Если да, облако может быть источником истины для учёта, а локальный сервис — для выдачи QR.
5. **Сеть**: доступен ли mini PC из мобильного приложения (VPN/проброс портов) или приложение ходит через облако.
6. **Права**: кто имеет право выдавать гостевые пропуска (жильцы, УК, консьерж) и есть ли лимиты.

## 5. Риски

- Панель ограничивает число identifier-ов (до 20 000) — достаточно для гостей, но нужна очистка.
- Лимит проходов и временные профили зависят от прошивки; на старых версиях может не быть.
- Гостевой QR, выданный через панель, нельзя «отозвать» мгновенно на всех панелях, если сеть до одной из них недоступна. Нужен механизм повторной синхронизации.
- Персональные данные гостей (ФИО, номер авто) подпадают под 152-ФЗ. Хранить минимум и с ограниченным сроком.

## 7. Проверка ответа «API BAS-IP: /api/access/identifier, /png, zones, max_passes»

Сверка с опубликованной документацией BAS-IP (developers.bas-ip.com, поиск по открытым страницам):

| Утверждение | Статус |
|---|---|
| Авторизация `Authorization: Bearer <token>` | Подтверждено для API панелей. Токен живёт 2 часа, refresh-токенов нет |
| `POST /api/access/identifier` с `type: "qr"`, `zones`, `max_passes`, `expires_at` | Не найдено. В документации: `POST /access/identifiers/item` (Android 1.8.0) и `POST /access/identifier/item` или `/access/identifier` в других версиях. Поля другие: время задаётся через time profile |
| `GET /api/access/identifier/{id}/png` | Не найдено в открытой документации |
| `POST /api/access/identifier/{id}/timeprofile` | Не найдено. Реально: `POST /access/identifiers/item/{uid}/timeProfile/{tpUid}` и `POST /access/timeprofile/item` |
| «Reset identifier left passes» | Не найдено |
| Версия API «v2.21.0» | Не найдена. Публичные версии: Android 1.8.0, Camdroid, 3.4.0 прошивки |

Вывод: пути и поля в ответе похожи на придуманные. Пути отличаются в разных версиях прошивки, поэтому их нужно проверить на самой панели. Plan: получить токен, вызвать `GET` на известных эндпоинтах и посмотреть Swagger/страницу API в веб-интерфейсе панели. Не опираться на текст без проверки.
